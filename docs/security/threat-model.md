# Security Threat Model: Agentic Travel Operations

## 1. Executive Summary & Security Philosophy

The **Agentic Travel Operations** platform operates under a strict principle of zero-trust autonomy:

> **LLM Proposes, Domain Validates, Infrastructure Executes.**

An Artificial Intelligence agent never receives direct mutation access to persistent databases, financial transaction ledgers, or external messaging infrastructure. Every proposed operational change generated by an LLM is treated as untrusted user input that must pass through deterministic domain boundaries, cryptographic verifications, and tenant-scoped policies.

## 3. Threat Model Matrix (STRIDE & OWASP LLM Top 10)

| Threat ID | Threat Category | Threat Description | Attack Vector | Security Mitigation | Verification Test Suite |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **THREAT-01** | Tampering / Elevation of Privilege | **Prompt Injection & Adversarial Jailbreak** | An attacker crafts Arabic or English prompts attempting to override operational rules, force illegal shifts, or reschedule immutable flights. | Deterministic Action Boundary (`action-validator.ts`) enforces business rules regardless of LLM output. Model output is parsed into strict Zod schemas and validated against immutable flags, operational windows, and transit buffers. | `tests/ai/ai-eval.test.ts`, `tests/domain/property-based-invariants.test.ts` |
| **THREAT-02** | Information Disclosure / SSRF | **Server-Side Request Forgery (SSRF)** | Malicious suppliers provide URLs pointing to cloud metadata services (`169.254.169.254`), loopback addresses (`127.0.0.1`), or private IP ranges (`10.0.0.0/8`, `192.168.0.0/16`). | DNS resolution checking with IP address validation (`src/lib/security/ssrf.ts`) rejects loopback, link-local, private IPv4/IPv6, and unsafe protocols before network egress. | `tests/ssrf.test.ts` |
| **THREAT-03** | Repudiation / Denial of Service | **Webhook Replay Attacks & Race Conditions** | Attackers or network retries replay identical webhook notifications to trigger duplicate cascades or concurrent DB updates. | Atomic check-and-set idempotency state machine (`idempotency.ts`) acquiring short-term in-flight locks and storing SHA-256 hashed message signatures. | `tests/idempotency.test.ts`, `tests/chaos/load-resilience.test.ts` |
| **THREAT-04** | Spoofing / Tampering | **Webhook Signature Forgery & Timing Attacks** | Unauthenticated callers forge WhatsApp Cloud API webhook requests. | Fail-closed HMAC-SHA256 signature validation using `crypto.timingSafeEqual` and timestamp freshness windows preventing replay window exploitation. | `tests/webhook-security.test.ts` |
| **THREAT-05** | Information Disclosure / Elevation | **Cross-Tenant Data Leakage** | A tenant supplies a valid event ID belonging to a competitor or different DMC. | Strict session-derived tenant isolation across all database queries (`.eq('tenant_id', tenantId)`). Absence of tenant credentials fails closed with HTTP 401. | `tests/integration/pipeline-integration.test.ts` |
| **THREAT-06** | Spoofing / Unauthorized Mutation | **Supplier Impersonation** | An unauthorized supplier or spoofed phone number attempts to shift an itinerary event owned by another guide or company. | Application-boundary semantic authorization (`TravelOperationsOrchestrator`) checks incoming phone number against registered tenant providers and verifies ownership of `experience_provider_id` before mutation. | `tests/domain/domain-authorization.test.ts` |
| **THREAT-07** | Denial of Service / Cascading Failure | **Outbox Delivery Exhaustion & Notification Drop** | Downstream supplier dispatch network errors cause dropped notifications or retry storm lockups. | Production-grade transactional outbox worker (`outbox-worker.ts`) with exponential backoff, jitter, maximum retry limits, and dead-letter queue (DLQ) state. | `tests/domain/outbox-worker.test.ts` |

## 4. Cryptographic Standards

- **HMAC Verification**: `sha256` HMAC with constant-time equality comparisons (`crypto.timingSafeEqual`).
- **Distributed Trace Context**: W3C Traceparent standard (`00-${traceId}-${spanId}-01`) using 32-character hex trace IDs and 16-character hex span IDs.
- **Idempotency Hashing**: SHA-256 hash over tenant identifier, event identifier, recipient phone, and payload string.
